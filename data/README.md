1. Dataset / Sample Name
Classroom Student Engagement Dataset
•	Version: As published on Kaggle (last updated ~5 months prior to access)
•	Author / Publisher: Ghulam Mustafa
•	Original Project: Computer Science Final Year Project, Lahore Garrison University
•	Purpose: Detect and track student engagement in classroom settings via object detection.
________________________________________
2. Source / How the Team Created It
•	Origin: Extracted frames from real classroom video footage.
•	Annotation Tool: Roboflow (Bounding Box Object Detection).
•	Annotation Density: Over 4,500 total bounding box annotations across 489 images.
•	Labeling: Manually labeled across 8 action classes.
•	Class Distribution:
Class	Annotations
look_forward	2,425
turn_head	725
using_device	527
read	347
write	331
sleep	236
stand	60
handrise	26
•	Class Imbalance Note: handrise (26) and stand (60) are severely underrepresented compared to look_forward (2,425). This will likely require mitigation (see Section 7).
•	Format: Images and labels in YOLOv11 format (compatible with YOLOv8).

4. Expected Folder Structure
The dataset is expected to follow a standard YOLO layout:
text
classroom-student-engagement-dataset/
├── dataset/
│   ├── images/
│   │   ├── image_001.jpg
│   │   ├── image_002.jpg
│   │   └── ...
│   └── labels/
│       ├── image_001.txt
│       ├── image_002.txt
│       └── ...
└── data.yaml   (may need to be created manually)
•	images/ — JPEG/PNG classroom frames.
•	labels/ — One .txt file per image, YOLO format: class_id x_center y_center width height (normalized 0–1).
•	data.yaml — May not be included. Often needs to be created manually (see Section 7).
•	On Kaggle, this is typically mounted at:
/kaggle/input/datasets/mustafaxgm/classroom-student-engagement-dataset/dataset/

5. Data Provision Method
•	How it is provided: Downloaded from Kaggle (not generated by us, not committed to the repo).
•	Committed to repo? No. The dataset (~129 MB, 964 files) is not committed to version control. It is pulled at runtime.
•	How to obtain it:
o	On Kaggle: Attach via "Add Input" in a notebook.

6. Preparation Needed Before the Run
The following steps must be completed before training:
1.	Create data.yaml (usually missing). Example:
yaml
train: /path/to/dataset/images
val: /path/to/dataset/images
nc: 8
names: ['handrise', 'look_forward', 'read', 'sleep', 'stand', 'turn_head', 'using_device', 'write']
2.	Create a proper train/val split. The Kaggle dataset does not ship with a validation set — split the 489 images (e.g., 80/20) so evaluation is meaningful.
3.	Verify label format. Confirm .txt labels are YOLO format and class IDs map correctly to data.yaml names.
4.	Check for corrupt or unlabeled images before training.
5.	Address class imbalance — consider oversampling handrise/stand or using class weights / augmentation.
6.	Verify the licence and consent status (Section 3) before any non-research use.
7.	Set up the environment:
bash
pip install ultralytics kagglehub
8.	Write outputs to a writable directory. On Kaggle, /kaggle/input/ is read-only — write weights and configs to /kaggle/working/.
9.	Save the trained weights (best.pt) and download them before the session ends.
